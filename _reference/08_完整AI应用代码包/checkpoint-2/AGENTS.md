# 图纸 AI 工程助手｜共享开发规则

## 产品契约

产品只有三个平级功能：`AI 审核`、`工艺路线`、`报价`。每个功能都必须能从 PDF 上传独立开始，不得以另一个功能的完成、确认或历史结果作为前置条件。

- AI 审核：直接生成可下载报告。
- 工艺路线：AI 提取图纸事实，公开参考资料包补齐课堂条件，直接生成路线卡。
- 报价：AI 和公开参考资料包补齐课堂成本假设，金额只能由程序公式计算。

共享部分只包括 PDF 接入、AI 设置、结构化提取、公开资料包、历史和 PDF 导出。

## 课堂原则

- 默认主方案是 Gemini＋DeepSeek，K3＋DeepSeek 作为国产备选。
- 产品只呈现三个独立功能和一个统一 API 设置入口；自动化测试使用本地测试夹具。
- 首次运行不要要求学员填写制造条件或成本参数；应自动补齐并清晰标记假设和来源。
- 保持界面和主路径极简。

## 安全边界

- 原 PDF、分页图、`runtime/private`、`.env.local`、API Key 和本机绝对路径不得进入 Git、响应、日志或报告。
- 只有用户主动点击运行某项功能时，才向视觉模型发送该次任务的分页图。
- DeepSeek 只能按需接收最小化结构化文本，不接收图片、PDF、绝对路径或密钥。
- 模型输出先经严格 Schema 和证据校验；坐标不可靠就拒绝，不猜测。
- 工艺路线不得声称是 NC 程序或投产参数。报价不得声称是商务要约。

## 固定验证

```bash
python3 -m unittest -v tests.test_milestone
python3 server.py --check
cd frontend && npm run lint && npm test
```

不得通过放宽契约、删除关键断言或把测试夹具冒充真实 AI 来制造绿灯。每轮交接记录：改了什么、跑了什么、结果是什么、还没验证什么。
