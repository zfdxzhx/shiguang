# 课堂带练任务卡｜真实递进版

> 本卡使用“阶段 A～E”描述图纸 AI 项目内部步骤，不对应正式课程表中的实战编号。

## 阶段 A｜Starter：先读懂产品

目标：

- 说清 AI 审核、工艺路线、报价三个功能为什么平级独立。
- 找到前端、后端、测试和启动入口。
- 确认 Starter 没有 PDF 路由，也没有 AI 产品路由。

验收：

```bash
cd starter
python3 -m unittest -v tests.test_milestone
python3 server.py --check
```

## 阶段 B｜Starter → CP1：PDF 与 API 基础

学员真正完成：

- `backend/intake.py`：PDF 文件头、大小、页数、SHA256 和私有分页。
- `backend/app.py`：上传、文档状态和本地页图路由。
- 前端：PDF 选择、第一页预览和统一 API 设置。
- API 设置只显示 Gemini＋DeepSeek 与 K3＋DeepSeek。

完成后使用 `checkpoint-1` 对照或恢复。

## 阶段 C｜CP1 → CP2：独立 AI 审核

学员真正完成：

- Provider：Gemini/K3 接收分页图；DeepSeek 只按需接收最小化文本。
- 严格 `ReviewDraftV2`：非法 JSON、空证据和弱坐标安全停止。
- 只注册 `POST /api/v1/features/review/runs`。
- 审核完成后直接生成可下载的 PDF 报告。

完成后使用 `checkpoint-2` 对照或恢复。该版本没有 process/quote 产品路由，工艺与报价模块是明确 TODO。

## 阶段 D｜CP2 → CP3：工艺、报价和完整产品

学员真正完成：

- 工艺：图纸事实 → 带来源参考数据包 → 加工路线卡。
- 报价：参考成本参数 → 确定性公式 → 参考报价单。
- 三个功能都从一份新 PDF 独立开始。
- 三个结果进入统一历史并分别下载 PDF。

金额必须可复算，参考值必须显示来源和“课堂假设”边界。

## 阶段 E｜CP3 → Golden：交付收口

1. 先运行 CP3 基线测试。
2. 对照 Golden 完成界面、报告和显式数量处理的最后优化。
3. Codex 独立审查，学员确认 findings，再做最小修复。
4. 重跑同一组测试与浏览器三路径。
5. 保存三份 PDF 和验收记录。

Golden 只用于演示、对照和严重故障恢复，不作为学员复制答案。

## 实时 API 彩排

离线门禁全部通过后，才使用一份已授权课堂图纸：

1. 选择 Gemini＋DeepSeek 或 K3＋DeepSeek。
2. 学员输入自己的 Key，优先“仅本次运行”。
3. 分别从三个入口运行，不复用另一功能的状态。
4. 记录 Provider、模型、授权、成功/失败、三份产物和未验证项。

没有授权、Key、网络或额度时，使用 Golden 完成本地测试、服务自检和浏览器路径验收。
