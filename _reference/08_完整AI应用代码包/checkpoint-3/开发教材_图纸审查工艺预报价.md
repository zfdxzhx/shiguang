# 图纸 AI 工程助手开发教材

副标题：带着学员从零开发三个独立 AI 功能

## 1. 这节课要做成什么

学员最终会得到一个可在本机打开的真实 Web 产品，而不是一个一次性脚本。产品只保留三个清晰入口：

1. `AI 审核`：上传图纸，直接得到《图纸 AI 审核报告》。
2. `工艺路线`：上传图纸，直接得到《AI 工艺路线卡》。
3. `报价`：上传图纸，直接得到《AI 参考报价单》。

三个入口平级独立，共享上传、AI 设置、结构化提取、历史和 PDF 导出能力。

## 2. 用户看到的最短路径

```text
AI 审核   ：PDF → AI 提取/审核 → 报告
工艺路线：PDF → AI 提取 → 参考条件 → 路线卡
报价      ：PDF → AI 提取 → 参考成本参数 → 公式 → 报价单
```

只有五项共享能力：

- PDF 上传、哈希与本地分页。
- 一处 API 设置。
- 一份严格的 AI 结构化输出契约。
- 一份带来源的公开参考资料包。
- 一个后端历史与 PDF 导出机制。

## 3. 当前模型分工

本项目由视觉模型直接读取 PDF 分页图，再由语言模型按需复核最小化结构化文本：

- 默认组合：Gemini 负责读图，DeepSeek 负责按需复核。
- 国产备选：K3 负责读图，DeepSeek 负责按需复核。
- DeepSeek 不接收图片、PDF、本机路径或密钥。

## 4. 当前产品运行方式

学员从统一的 API 设置入口配置一个模型组合，然后在任意功能卡上传图纸并直接运行：

- 页面只呈现 AI 审核、工艺路线和报价三个功能。
- 每次运行都记录实际使用的 Provider、模型、状态和产物。
- 运行失败会显示可理解的错误，并保留再次运行入口。
- 自动化测试使用本地测试夹具验证代码契约，不产生产品记录。

## 5. 数据补齐策略

学员第一次运行工艺或报价时，不需要手工填制造条件和成本条件。程序按以下顺序处理：

1. 视觉模型从图纸提取零件名称、版本、材料、尺寸、公差和图纸类型。
2. 程序将场景匹配为 CNC、钣金、注塑或装配。
3. 从版本化公开资料包取得制造方法、成本结构、价格趋势和标准索引。
4. 用明确的课堂假设补齐数量、材料单价、损耗、工时、设备费率、工装、管理费、风险和毛利率。
5. 在结果页与 PDF 中展示来源、假设和使用边界。

这是“AI＋公开资料查询”，但为了课堂稳定，不要再要求第三个搜索服务的 API Key。教学延伸任务可以再把资料包替换成实时搜索插件。

## 6. 报价必须由公式算

核心成本项：

```text
材料成本 = 净重 × (1 + 损耗率) × 材料单价 × 数量
设备成本 = (调机小时 + 单件加工分钟 × 数量 / 60) × 设备时费
直接成本 = 材料 + 设备 + 工装 + 外协 + 检验包装 + 物流
管理成本 = 直接成本 × 管理费率
风险成本 = (直接成本 + 管理成本) × 风险率
目标收入 = 总成本 / (1 - 目标毛利率)
单件参考报价 = 目标收入 / 数量
```

模型可以帮助选场景、补齐参考输入和解释假设，但不能直接输出最终金额并覆盖公式。

## 7. 最小架构

```text
frontend/
  app/drawing-review-app.tsx   三个入口、三种结果、历史、设置
backend/
  app.py                       API 路由
  intake.py                    PDF 本地校验与分页
  providers.py                 Gemini/K3/DeepSeek
  models.py                    严格 Schema
  reference_profiles.py        带来源的参考数据
  workflows.py                 工艺模板与报价公式
  service.py                   独立运行、历史与导出
  pdf_report.py                AI 审核报告
  process_plan_pdf.py          工艺路线卡
  quote_report.py              参考报价单
```

## 8. API 契约

三个入口只有 `feature` 不同：

```http
POST /api/v1/features/review/runs
POST /api/v1/features/process/runs
POST /api/v1/features/quote/runs
Content-Type: application/json

{
  "document_id": "doc-...",
  "external_processing_consent": true
}
```

查询与下载：

```http
GET /api/v1/features/runs/{run_id}
GET /api/v1/features/runs/{run_id}/report
GET /api/v1/features/history
```

不要为三个功能设计三套上传、三套 API 设置和三套历史。

## 9. 学员带练切片

### Starter：看到目标

- 打开 README 和测试。
- 启动一个只有首页三卡片的骨架。
- 理解三个功能为什么必须平级。

### Checkpoint 1：PDF 接入

- 完成 PDF 头、文件大小、页数和 SHA256 校验。
- 只在本机保存原 PDF 和分页 PNG。
- 前端完成选择文件与第一页预览。

### Checkpoint 2：AI 审核

- 配置 Gemini＋DeepSeek 或 K3＋DeepSeek。
- 定义严格 `ReviewDraftV2`。
- 拒绝无证据问题、无效 JSON 和不可靠坐标。
- 直接生成《图纸 AI 审核报告》。

### Checkpoint 3：工艺与报价

- 添加带来源的参考资料包。
- 从一份新 PDF 独立生成工艺路线卡。
- 再从另一份新 PDF 独立生成参考报价单。
- 验证报价不读取审核或工艺历史。

### Golden：完整产品

- 统一首页、历史和 API 设置。
- 三个功能都有结果页和 PDF 下载。
- 失败时显示可理解的安全错误。
- 自动化测试、前端构建和浏览器检查全部通过。

## 10. 课堂 API 设置

每个学员在页面右上角点“设置”。建议选“仅本次运行”：

1. 选择 Gemini＋DeepSeek（推荐）或 K3＋DeepSeek（国产备选）。
2. 填入模型 ID 和 API Key。
3. 保存。密钥只在当前 Python 进程内存中存在。
4. 关闭本地服务后密钥自动消失。

个人电脑可选“保存到本机钥匙串”，公共机房不建议。

## 11. 端到端验收

先跑离线自动化测试：

```bash
python3 -m unittest -v tests.test_milestone
python3 server.py --check
cd frontend
npm run lint
npm test
```

然后在浏览器中使用已授权图纸，依次验证：

- 审核入口可以直接下载审核报告。
- 工艺入口可以直接下载路线卡。
- 报价入口可以直接下载报价单。
- 结果页可以展开查看来源和假设。
- 历史页分别展示审核、工艺和报价记录。

实时验收必须单独记录使用的 Provider、模型、授权、成功/失败和实际产物。自动化测试通过后，仍需完成一次真实 API 运行验收。

## 12. 三句不能删的边界

1. AI 审核报告不是正式工程批准。
2. AI 工艺路线卡不是 NC 程序或投产工艺。
3. AI 参考报价单不是商务要约或正式报价。

课堂目标是让学员看到“数据从哪里来、AI 做了什么、程序做了什么、边界在哪里”，而不是把一份教学输出包装成生产批准。
